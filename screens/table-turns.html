Math

Where the $680 comes from — formula trace, inputs, exclusions, the $68 gap
ƒThe formula trace · Oakland Friday Dinner ▾
Theoretical turns = (4 hrs × 60) ÷ 76 min target = 3.16 turns/seat Actual turns = (4 hrs × 60) ÷ 94 min actual = 2.55 turns/seat Turn deficit = 3.16 − 2.55 = 0.61 turns/seat Theoretical lost = 0.61 × 42 seats = 25.6 covers/service Realization haircut × 36% (East Bay full-service casual) Lost covers/service = floor(25.6 × 0.36) = 9 Revenue/service = 9 × $76 avg check = $684 Weekly (1 Fri/wk, floored) = ~$680 Monthly run-rate = $680 × 4.33 = ~$2,944/mo

Lost covers always floored, never rounded up. Realization haircut applied before flooring.

◉Inputs ▾

Operator-configurable inputs (seats, target, haircut) live in Settings → Service Profile.

⊘Exclusions enforced before math ▾
DINE_IN only. TAKE_OUT and DELIVERY have no meaningful dining duration and are excluded entirely.
Voided checks excluded. Voids don't represent real cover throughput.
Still-open checks excluded from closed-period analysis.
Comped services excluded from avg-check baseline. Comps distort revenue/cover.

All exclusions are applied before the math runs.

⚠Why the playbooks don't sum to $680 ▾

Playbook estimates are independent point estimates per intervention. Applying multiple playbooks doesn't strictly add — overlapping stage effects mean Playbook 1 + Playbook 2 < the sum of their individual estimates.

Playbook 1 (Dessert menu at 60 min) = $420/wk Playbook 2 (Pre-bus during entrée) = $148/wk Playbook 3 (QR self-close) = $44/wk Sum of estimates = $612/wk Headline opportunity = $680/wk Residual gap = ~$68/wk

The residual ~$68/wk is unclaimed and may indicate optimization opportunities not yet codified into a playbook.

Rules

Mode, guardrails, confidence thresholds, and the filters that run before any math
◐KDS vs Proxy mode ▾
KDS MODE · default. Toast KDS provides per-stage timing (Seated→Order, Order→Food, Eating, Dessert→Check). Stage decomposition active. All Watch panels render with per-stage detail.
PROXY MODE · KDS data missing. Total duration only (seat → close), no stage decomposition. Outputs labeled [Proxy · KDS unavailable] / [HEU · rule-of-thumb].

Mode is determined per-service-period, not per-account. Auto-switches based on KDS feed availability.

◎Guardrails (verification-side) ▾
Avg check must not drop during the monitoring window. Per-cover spend tracked per service.
Guest sentiment must not worsen. Tracked via review platforms + complaint patterns.
Complaints / 100 covers must not rise. Front-line rushing signal.
Manager override allowed at any point. Pauses the monitoring window; resumes on resume.

Faster turns are not counted as verified recovery if check or sentiment degrades — even if covers/service improved.

%Confidence rules ▾

Confidence reflects KDS feed health, sample size, and pattern strength. Proxy mode is workable but capped.

⧫Filters applied ▾
DINE_IN only. TAKE_OUT and DELIVERY excluded.
Voided checks excluded.
Still-open checks excluded from closed-period analysis.
Comped services excluded from avg-check baseline.

All filters are enforced before duration math runs.

Restrictions

What the LLM can't do, what the platform forbids, and what blocks the math
⚠LLM restrictions ▾

Claude (Sonnet) generates plain-English summaries on Watch and Decide, but is not permitted to:

— Override the realization haircut or seat capacity.
— Round lost covers up. Floor rule is hard.
— Call estimated revenue "saved" or "recovered" in any output.
— Suppress Proxy/Heuristic labels when KDS data is unavailable.
— Re-rank stage bottlenecks. Bottleneck = stage with largest absolute overage AND ≥50% of total overage.
— Invent or reorder playbooks on Decide. Ordering is by $ impact desc, then confidence desc.
— Promote a sub-70% confidence playbook to the "ready" tier.

LLM outputs are decision-support only. Final authority is the operator.

⊗Use restrictions ▾

Per SKC Terms of Service, Table Turns outputs may not be used as the sole input for:

— Server scheduling decisions (don't punish slow nights with worse shifts)
— Disciplinary action against servers or managers
— Termination

Allowed use cases:

— Service-design changes (procedural, training, tech-enabled)
— Coaching conversations and shift huddles
— Capacity / staffing analysis

Final personnel decisions remain with the operator. SKC data is one input among many.

⊘Data state blockers ▾
POS down > 6h → detection paused for affected period.
KDS stale > 24h → mode auto-switches to Proxy; confidence capped.
Sample < 4 services → no detection generated for that daypart.
>5% of checks > 180 min → likely forgotten open checks; anomaly banner on Watch.
Missing avg check → dining-duration analysis available, but no revenue estimate.

All current blockers visible in Data Quality.
