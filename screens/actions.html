Action Evidence
Status rules, verification logic, guardrails, and workflow definitions. This page defines how actions move between Pending, Active Recovery, Ready to Verify, Blocked, and Verified — and what blocks each transition.
Status definitions
PENDINGAwaiting decision
ASSIGNEDOwner assigned, not implemented
IMPLEMENTEDOperating change in place, day 0
MONITORINGIn window, guardrails tracked
READYWindow complete, guardrails pass
VERIFIEDIn ROI Proof, counted
BLOCKEDCannot proceed (DQ/approval)
REJECTEDOperator declined
Verification logic

An action moves to VERIFIED only when all of the following hold:

1. Monitoring window complete (default 28 days · category-specific).
2. All guardrails hold for the full window — no breaches.
3. Source data is fresh (no stale-source confidence penalty active).
4. Owner review/sign-off completed in ROI Proof.

Until all 4 conditions are met, the action's value is [ACT · in monitoring] or [EST · not guaranteed] — never counted as Verified Savings.

Guardrails (default)
Labor — Ticket time must not worsen. Guest sentiment must not drop. Sales/throughput must not fall.
Menu — Unit decline ≤ 7%. Sentiment stable. Refund rate stable.
Table Turns — Avg check stable. Sentiment stable. Faster turns not counted if either degrades.
Manager override — Allowed at any point. Override pauses the monitoring window; reset on resume.
Financial label rules
[EST · not guaranteed]Pre-implementation projection
[SIM · what-if]Modeled lift, not yet attempted
[ACT · in monitoring]Tracking in monitoring window
[VER · counted]Counted in ROI Proof
[BLOCKED]Excluded from all counts

Every dollar value carries time basis, output type, and a derivation link to evidence. Never "saved" or "recovered" until all 4 verification conditions hold.

Workflow transitions
Detected (Profit Recovery) → Pending Pending + Operator approval → Assigned Assigned + Implemented → Monitoring Monitoring (window complete + guardrails OK) → Ready Ready + Owner verification → Verified (ROI Proof) Any state + DQ failure or approval gate → Blocked Any state + Guardrail breach → Reverted / Failed
LLM restrictions

Claude (Sonnet) generates action recommendations and rationale, but is not permitted to:

— Set status to Verified. Verification is rule-driven, not LLM-driven.
— Override guardrails. Manager override only.
— Call estimated/simulated values "saved" or "recovered" in any output.
— Skip the monitoring window or shorten it without operator approval.

All financial outputs are decision-support only; the operator is the final authority.
