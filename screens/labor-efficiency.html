Threshold rules
RPLH floor: $36.50/hr. Below this, the service is flagged as a labor productivity leak signal. Floor is recalibrated quarterly against peer P25.
Labor % ceiling: 31.0%. Above this, labor cost is flagged as outside target band. Target is restaurant-specific (full-service casual dining, no delivery).
Minimum sample: 4 comparable services in the trailing window. Fewer = no detection. Prevents single-service noise from generating false leaks.
Daypart normalization: RPLH is always compared to same-daypart baseline. Tuesday lunch RPLH is not compared to Saturday dinner RPLH.
Confidence floor: Below 60% source confidence, no detection is generated. Source confidence reflects POS sync freshness and 7shifts token state.

Labor Evidence
Formulas, sources, confidence rules, data-quality blockers, and LLM restrictions. This page defines how labor leaks are detected and what blocks verification.
Formula trace
RPLH = Net sales ÷ labor hours Excess hours = scheduled − required Required = covers ÷ covers-per-server target Weekly $ = excess hrs × loaded wage × services/wk Loaded wage = base + tax + WC + benefits Monthly run-rate = weekly × 4.33

RPLH is diagnostic only. Dollar recovery is computed from excess hours × loaded wage, not from RPLH directly.

Toast POS · connected · live

Confidence rules
Floor for detection60%
Floor for action70%
Floor for verification80%
Stale 7shifts penalty−7 pts
Stale POS penalty−12 pts
Missing wage data−15 pts

Confidence is a function of source freshness, sample size, and pattern strength. Below 70% = pending only, no auto-action.

Guardrails (verification-side)
Ticket time must not worsen during monitoring window. Measured per service vs baseline.
Guest sentiment must not drop. Tracked via review platforms + complaint patterns.
Sales / throughput must not fall. If covers drop >5% with staffing held constant, guardrail trips.
Manager override allowed at any point. Pauses monitoring window; resumes on resume.

Staffing reduction is not counted as verified if service quality degrades, even if labor cost dropped.

Data-quality blockers
POS down > 6h → detection paused for affected period.
7shifts stale > 24h → detection continues but confidence reduced.
Wage data unconfirmed → dollar values labeled [ESTIMATED · WAGE UNCONFIRMED]; cannot move to action.
Sample < 4 services → no detection generated.

Server Coaching methodology

Primary metric: Premium item attach rate.

Attach % = checks w/ premium tag ÷ total checks

Secondary metrics: items/check, modifier capture, comp rate.

Peer group:

Same daypart × section type × location. Min 3 peer servers required.

Sample floor:

12+ shifts in trailing 60 days per server. Below floor = no ranking.

Surfaced output:

Top quartile (assets) + bottom quartile (opportunities). Middle 50% intentionally hidden — not actionable as coaching targets.

Deliberately excluded:

Tip percentage. Correlates with section assignment and party demographics, not service quality. Including it would generate structurally biased rankings.
Total tips, total sales. Confounded by section, daypart, party size. Not server-attributable.
Composite "performance score". Hides what's being measured. Each metric stays decomposable.
Server Coaching · use restrictions

Per SKC Terms of Service, Server Coaching outputs may not be used as the sole input for:

— Scheduling decisions (which servers get which shifts)
— Promotion or demotion decisions
— Disciplinary action
— Termination

Allowed use cases:

— Coaching conversations and training
— Shadow training pairing (top performer + new hire)
— Recognition and morale
— Identifying section/daypart structural issues

Final personnel decisions remain with the operator. SKC data is one input among many.

LLM restrictions

Claude (Sonnet) generates labor analysis and natural-language summaries, but is not permitted to:

— Set or modify confidence scores. Confidence is rule-driven.
— Override RPLH thresholds or wage assumptions.
— Call estimated values "saved" or "recovered" in any output.
— Auto-create actions. Operator approval required.
— Generate language about a server's character, attitude, or perceived motivation. Only measurable behavior in metrics.
— Compare servers across different peer groups. Daypart/section/location must match.

LLM outputs are decision-support only. Final authority is the operator.
