## How to implement

- **Per-cell RPLH:** prefer measured `rev / hrs`; fall back to `baseline × score/100` only when measured hours are missing. Never divide by zero — excluded/zero-revenue cells stay N/A (gray).
- **Sparkline data:** the production equivalent of `LE_RECURRING_PATTERNS` is a 6-element array of weekly productivity scores per shift, most-recent week last (it gets the `le-hmd-spark-current` highlight). The caption counts how many of the 6 weeks fell below the 85 baseline.
- **Confidence tiers map to doctrine floors, not arbitrary colors:** ≥ 80% = verification-eligible (green · ready); 70–79% = actionable but review-only (amber · review); < 70% = below action floor (red · hold). Drive the badge text and the `le-sf-item-conf-*` class from the same confidence value.

## Known caveats in this version

- **Heatmap subpage filters are spec-only.** The Location, Daypart, and Severity selects (and the top-right Period selector) call `showDemoToast()` purely for demo affordance — they don't actually filter the heatmap. In production they must re-query `LE_HEATMAP_DATA` (or its server equivalent) and re-color cells. Severity = filter cells where the productivity score crosses the corresponding threshold (≥85 / 70–84 / &lt;70).
- **Heatmap "Now" cursor is hardcoded** to `data-day="Wed"` / `data-hour="11A"` via a CSS attribute selector in `shared/styles.css`. In production, compute the current day-of-week + hour and set those data attributes (or a `.le-heatmap-cell-now` class) at render time.
- **Focal-shift cell outline is hardcoded** to `Tue` 11A–2P via the same CSS attribute-selector pattern. In production, the outlined cells should be driven by whichever shift is named in the focal eyebrow (currently "Oakland · Tuesday · Lunch"). Drive both from the same focal-shift object — eyebrow text and outlined cells must agree.
